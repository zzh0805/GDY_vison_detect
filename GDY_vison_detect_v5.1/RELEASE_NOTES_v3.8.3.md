# GDY Vision Detect v3.8.3

发布日期：2026-09-18

## 版本目标

本版本重点解决 SurfacePro50 网络相机在正式服务中可能读取旧彩色帧、固定丢帧等待导致响应过慢，以及客户端超时断开后服务端产生 Broken Pipe 异常的问题。同时合并 v3.8.0 至 v3.8.2 的交互式工具标定和现场流程改进。

## 主要更新

### 1. 最新帧后台缓存

- 相机连接后启动后台取流线程，持续消费 OpenNI 队列；
- 后台仅复制彩色、深度各自的最新原始帧，不执行检测、点云和软件配准；
- 正式请求不再先固定等待4秒清队列，降低正常请求耗时；
- 快照和实时解算共用同一套最新帧策略。

### 2. 彩色为主的彩深选择策略

- 请求到达后优先等待请求后的下一张彩色帧，默认最长3秒；
- 彩色帧确定后，选择其后到达的深度帧用于三维解算；
- 如果3秒内没有新彩色帧，在机器人已到位并保持静止的现场前提下允许使用现有彩色缓存，不再因为彩色帧不递增直接失败；
- 日志明确标记“请求后新帧”或“3秒超时后接受缓存”。

### 3. 厂家帧元数据兼容

- `frameIndex`、`timestamp` 为0、缺失或非有限值时不参与递增判断；
- 保留有效元数据的日志记录，但不把厂家无效字段当作旧帧证据；
- 新增彩深软件序号、到达时间差、缓存回退状态等诊断字段。

### 4. 性能和网络诊断

- 新增 `field_test/13_surfacepro50_stream_rate.py`，可分别测试彩色流和彩深流实际速率；
- 启动日志记录分辨率、像素格式、每组原始数据量和曝光参数；
- 现场1920x1080彩色帧大小约6,220,800字节，在百兆交换机上实测约2.064fps，与100Mb/s带宽上限基本吻合；
- 建议相机、交换机、主机网卡和网线全链路使用千兆。Jumbo Frame只能减少少量协议开销，不能把百兆链路提升为千兆。

### 5. 服务稳定性

- HTTP客户端已超时或主动断开时，单独处理 `BrokenPipeError`、`ConnectionResetError` 和 `ConnectionAbortedError`；
- 不再尝试向已经关闭的连接二次发送500响应；
- 后续视觉请求不受该连接异常影响。

### 6. v3.8系列功能汇总

- 新增一次运行完成工件选择、位姿读取、计算、备份和写回的交互式工具标定；
- 工具偏移和目标中心策略支持热加载；
- 现场测试支持保持在工作TCP、不返回拍照位；
- 现场测试的实时拍照模式、安装面板标签和工件code可以直接从配置读取；
- YOLO模型由 `models/xuncao.pt` 更新为 `models/best.pt`。

## 配置变化

`config/workflow.yaml`：

```yaml
http:
  snapshot_delay_s: 0
  live_capture_delay_s: 0

camera:
  fresh_frame_timeout_s: 3.0

yolo:
  model_file: ../models/best.pt
```

`fresh_frame_timeout_s` 表示优先等待请求后新彩色帧的最长时间。达到该时间后，如果后台已有彩色缓存，则按照静止拍照位前提继续处理。

## 接口兼容性

- `/snapshot`、`/get_tcp_pose` 和 `/motion/get_tcp_pose` 的请求格式保持不变；
- TCP解算坐标链和工具偏移结构保持兼容；
- 正式服务仍只计算目标TCP，不直接控制机械臂运动；
- 机械臂到位后的稳定等待仍应由上位流程负责。

## 部署提示

1. 替换本版本代码和 `models/best.pt`；
2. 检查 `config/workflow.yaml` 与现场配置；
3. 确认相机网络链路协商为 `1000Mb/s Full Duplex`；
4. 重启视觉服务并观察“SurfacePro50流诊断”和“拍照帧就绪”日志；
5. 使用流速诊断脚本复测彩色帧率；
6. 连续执行多次完整流程，统计平均耗时和最大耗时。

## 已知限制

- 百兆交换机将1920x1080原始彩色流限制在约2fps，属于网络硬件带宽限制；
- 厂家SDK可能返回0或不稳定的硬件时间戳，因此软件序号与主机到达时间是主要诊断依据；
- 彩深选择依据主机到达顺序，不等同于相机硬件同步；
- `color-depth` 独立诊断曾出现厂家OpenNI原生库抛出 `std::system_error` 并终止进程，需结合千兆链路、厂家驱动版本继续验证；正式服务应保留进程守护和自动重启。
